# 标题结构库 · V1.1.0

## 来源与边界

早期设计参考了 2026-10-14 从微信读书界面整理的「数字生命卡兹克」233 条可见标题，时间范围为 2025-10-14 至 2026-10-14。可见列表不保证覆盖删除、缺失或未加载的文章，也不能据此推断标题带来的点击效果。

公开版提供抽象结构与自写示例，不附第三方标题原文集合、私人研究文件或用户稿件。下表例句均为虚构演示，不是该作者的原题，也不是已经发生的事实。使用时必须回到用户母稿核对。项目与该公众号无隶属或背书关系。

## 可选择的结构

| 结构 | 自写演示句式 | 使用条件 |
|---|---|---|
| 亲自行动＋具体投入＋产物 | 我用一个周末，把家里的书整理成了一张清单 | 母稿有真实行动、投入和产物；不能编时间或成果 |
| 任务＋起点或门槛＋教程 | 第一次整理家庭账单，可以从这3步开始 | 正文有对应步骤和适用前提；不能暗示所有人都能得到同样结果 |
| 筛选依据＋数量＋可用内容 | 这5个我反复使用的会议记录问题，分享给你 | 数量与正文清单一致；他人的经验不能写成自己的常用清单 |
| 产品变化＋判断＋场景意义 | 导出时能保留批注了，交接文档少了一次手工整理 | 母稿说明了真实变化与适用场景；局部方便不能扩成行业结论 |
| 真实限制＋意外发现 | 只用手机拍摄，反而让我先想清楚每个镜头 | 母稿有真实限制与观察；没有反差就不造反差 |
| 具体见闻＋反应＋问题 | 看到一张只有三列的预算表，我开始重看自己的记账习惯 | 见闻真实，正文能解释反应与问题；不补虚构现场 |
| 人物＋辨识度＋行动 | 一位乡村老师，给班里的旧电脑做了份维修手册 | 身份、行动与结果有来源；不堆与内容无关的猎奇细节 |
| 对象＋待回答的问题 | 每月的工具订阅费，哪些值得继续付？ | 正文确实回答具体问题；不能只有悬念而没有信息 |

## 组合原则

- 一条标题先选一个主结构，必要时再加入一个有依据的事实锚点，不叠满所有结构。
- 母稿主要是建议时，优先任务、问题或选择依据；母稿有实际经历时，再考虑亲历和结果。没有反差就不造反差。
- 同一事实可从读者问题、作者发现、决策建议三个角度写；不同角度应该改变信息焦点，不是只换同义词。
- 原稿已表达有力时，不为套句式让标题变长或换掉用户语气。例句中的数字、身份与结果不能作为用户母稿的证据。

## 向副标题与摘要迁移

“对象具体、收获清楚、依据可找、条件保留”适用于所有位置。主标题负责最强的一个理由；副标题补充让它成立的信息；摘要把承诺讲完整。三者共同指向同一篇内容。

副标题和摘要并未出现在上述标题采集样本中，抖音适配也没有由该样本验证。迁移方案属于本 Skill 的设计假设，应通过自己的真实母稿、用户选择和后续平台数据逐步改进；不能宣称是作者的实证爆款公式。
